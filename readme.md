## Intro

This is a project born from the 2023 Looker hackathon. It uses the Looker SDK and some metadata from dbt to automatically generate [dbt Exposures](https://docs.getdbt.com/docs/build/exposures).

This lets you keep your dbt exposures up to date without manually writing the YAML for them, or going through the tedious process of figuring out what models your dashboards reference. With your exposures up to date and accurately catloging the models your dashboards reference, when a model or test produces an error, you can easily answer the age-old question of 'Something in dbt broke. What dashboards is this impacting?'

Once you've updated your exposures, you might consider implementing [Elementary Data](https://github.com/elementary-data/elementary) to enhance your dbt instance's data observability and generate an enhanced lineage graph that lets you see what Looker Dashboards are impacted by the thing your data engineering team just broke.

## How It Works

<details>
<summary>Click to expand: Detailed workflow explanation</summary>

This tool creates a bridge between Looker and dbt by automatically discovering the dependencies between your Looker dashboards/looks and your dbt models. Here's the end-to-end workflow:

### 1. Read dbt Catalog

The tool reads your `catalog.json` file (generated by `dbt docs generate`) which contains metadata about all your dbt models including:
- Database/catalog name
- Schema name
- Table/view name
- dbt model name

It builds a lookup dictionary that maps SQL table names (like `catalog.schema.table`) to their corresponding dbt model references (like `ref('model_name')`).

### 2. Fetch Looker Content

Using the Looker API, the tool retrieves:
- **Dashboards** - Individual dashboard metadata and all dashboard elements
- **Looks** - Saved Looker queries/visualizations
- **Folders** - All dashboards and looks within a folder

For each piece of content, it extracts:
- Title, creator, and URL
- All queries associated with dashboard elements (including merge queries and LookML dashboard queries)

### 3. Extract SQL Queries

For each dashboard element or look, the tool:
- Calls the Looker API to get the actual SQL query that will be executed
- This is the compiled SQL that Looker sends to your data warehouse

### 4. Parse SQL to Find Tables

Using [sqlglot](https://github.com/tobymao/sqlglot), the tool parses each SQL query to extract all table references:
- Identifies fully qualified table names (e.g., `hive_metastore.analytics.orders` or `prod.analytics.customers`)
- Filters out temporary tables and CTEs (Common Table Expressions)
- Normalizes table names (lowercase, removes quotes/backticks)
- Deduplicates across all queries in a dashboard

### 5. Map Tables to dbt Models

For each table found in the SQL:
- Looks it up in the dbt catalog dictionary
- Converts it to a dbt `ref()` expression (e.g., `ref('orders')`)
- Tracks any tables that can't be mapped (these may be from other dbt projects or non-dbt sources)

### 6. Generate Exposure YAML

Creates a dbt exposure YAML structure for each dashboard/look:

```yaml
version: 2
exposures:
  - name: executive_dashboard
    label: Executive Dashboard
    type: dashboard
    url: https://looker.company.com/dashboards/123
    owner:
      name: john.doe
    depends_on:
      - ref('fact_orders')
      - ref('dim_customers')
      - ref('fact_revenue')
```

The output is printed to stdout, ready to be copied into your dbt project's YAML files.

### Why This Matters

With dbt exposures properly configured:
- **Impact analysis**: When a dbt model fails, instantly see which dashboards are affected
- **Lineage graphs**: Visualize the complete data flow from raw data → dbt models → Looker dashboards
- **Documentation**: Automatically document which business users/dashboards depend on your data models
- **Testing strategy**: Prioritize testing for models that power critical dashboards

</details>

## Pre-Requisites

Before running this tool, you need:

1. **Python 3.7+** installed on your machine
2. **A functioning dbt project** that generates the tables/views referenced by your Looker dashboards
3. **Access to dbt catalog** - Either:
   - dbt installed locally to run `dbt docs generate`
   - Access to dbt Cloud to download the catalog.json file
4. **Looker API credentials** with permissions to:
   - Retrieve dashboards and looks
   - Retrieve and compile queries
   - Access merge queries

## Setup Instructions

<details>
<summary>Click to expand: Step-by-step setup guide</summary>

### 1. Clone the Repository

```bash
git clone <repo-url>
cd looker_dbt_exposure_generator
```

### 2. Set Up Python Environment (Recommended)

Create a virtual environment to isolate dependencies:

```bash
# Create virtual environment
python -m venv venv

# Activate it
source venv/bin/activate  # On macOS/Linux
# OR
venv\Scripts\activate  # On Windows
```

### 3. Install Dependencies

```bash
pip install -r requirements.txt
```

This will install:
- `looker-sdk` - For interacting with the Looker API
- `sqlglot` - For parsing SQL queries
- `pyyaml` - For generating YAML output

### 4. Create Looker API Configuration

Create a `looker.ini` file in the project directory with your Looker API credentials:

```ini
[Looker]
base_url=https://your-looker-instance.cloud.looker.com:19999
client_id=your_client_id
client_secret=your_client_secret
verify_ssl=true
```

See [Looker API documentation](https://developers.looker.com/api/getting-started) for how to generate API credentials.

### 5. Generate and Copy dbt Catalog

```bash
# Navigate to your dbt project
cd /path/to/your/dbt/project

# Generate the catalog
dbt docs generate

# Copy catalog.json to the tool directory
cp target/catalog.json /path/to/looker_dbt_exposure_generator/
```

**Note**: The `catalog.json` file must be in the same directory as `dbt_exposure_generator.py` when you run the tool.

### 6. Verify Setup

Check that you have all required files in the same directory:
```bash
ls -la
# Should show:
# - dbt_exposure_generator.py
# - looker.ini
# - catalog.json
# - requirements.txt
```

</details>

## Usage


### Single Dashboard

Generate an exposure for a specific dashboard:
```bash
python dbt_exposure_generator.py --dashboard DASHBOARD_ID
```

### Single Look

Generate an exposure for a specific look:
```bash
python dbt_exposure_generator.py --look LOOK_ID
```

### All Dashboards in a Folder

Generate exposures for all dashboards in a folder:
```bash
python dbt_exposure_generator.py --folder FOLDER_ID
```

### All Content in a Folder (Dashboards + Looks)

Generate exposures for both dashboards and looks in a folder:
```bash
python dbt_exposure_generator.py --folder FOLDER_ID --all
```

### Multiple Items

You can process multiple dashboards, looks, and folders in a single command:
```bash
python dbt_exposure_generator.py \
  --folder FOLDER_ID1 FOLDER_ID2 \
  --look LOOK_ID \
  --dashboard DASHBOARD_ID456 DASHBOARD_ID789
```

### Saving Output

The tool prints YAML to stdout, so you can redirect it to a file:
```bash
python dbt_exposure_generator.py --folder 123 > exposures/looker_dashboards.yml
```

Or append to an existing file:
```bash
python dbt_exposure_generator.py --dashboard 456 >> exposures/looker_dashboards.yml
```


## SQL Dialect Support

This tool supports **Databricks** SQL dialect (both Hive Metastore and Unity Catalog naming conventions).

### Naming Conventions

The tool automatically handles both Databricks naming formats:

- **Hive Metastore**: 2-part table names (`database.table`)
- **Unity Catalog**: 3-part table names (`catalog.schema.table`)

The flexible lookup system matches tables correctly regardless of which format your environment uses, making it compatible during Unity Catalog migration periods when both formats may exist.

### Technical Details

- Uses [sqlglot](https://github.com/tobymao/sqlglot) for SQL parsing
- Automatically filters out CTEs (Common Table Expressions) and temporary tables
- Normalizes table names for case-insensitive matching
- Handles quoted identifiers (backticks, quotes)
